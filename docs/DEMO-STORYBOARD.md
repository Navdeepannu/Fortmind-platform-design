# 90-second product demo storyboard

| Time | Screen | On-screen action | Narration objective | Gate |
| --- | --- | --- | --- | --- |
| 00–08 | Home / Operations | Show needs-you queue and automation indicators | OSCAR investigates by default | Verify counts |
| 08–20 | OSCAR activity | Show an actual running stage or **labeled recorded example** | What OSCAR is doing and what it has completed | No fabricated live telemetry |
| 20–38 | Cases | Scan, filter, open side preview | Analyst stays in context | Keyboard, width and loading states |
| 38–57 | Case detail | Navigate verdict → hypothesis → finding | Show traceable decision-making | Validate evidence semantics |
| 57–69 | Integrations | Show tool coverage and health summary | Breadth of enrichment tools | Do not present failing tools as healthy |
| 69–83 | Impact / Reports | Show a real date period and validated metric | Quantifiable operational impact | Check math, sample size and units |
| 83–90 | Closing | Clean product frame | Autonomous investigations; human oversight | No personal information |

## Capture checklist

- Use consistent viewport, zoom, browser and theme per before/after comparison.
- Use intentional seeded **demo data** only when authorized and clearly distinguish simulated from production.
- Disable or crop user avatars, emails, org identifiers and secret-like values.
- Avoid hover states, editor toolbars, debug overlays and flaky loaded data during final recording.
- Confirm selected tabs, breadcrumbs, export labels and page controls match what the narration claims.
